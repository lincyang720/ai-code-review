## [1.0.0] - 2026-10-10

首个正式版本。基于 某真实项目 4753 个Java 文件的实测基线。

### 新增

- **CLI 全局命令**：`npm install -g .` 后任意目录可直接调用 `ai-code-review`
- **`--version` / `--help`**：版本号从 jar manifest 读取，单一事实源
- **`AI_REVIEW_JAVA_OPTS`**：环境变量，传额外 JVM 参数（如 `-Xmx4g`）
- **`--enable <规则号>`**：开启默认关闭的规则（如 `NORM-002`）
- **`--all-rules`**：开启全部规则
- **Skill 定义**：`SKILL.md` + `docs/CI.md`，可被 AI 助手直接加载
- **CI 集成示例**：GitLab CI / Jenkins / GitHub Actions 三套现成配置
- **三份输出材料**：控制台摘要（决策者）、`review-report.md`（技术负责人）、
  `gitlab-comment.md`（工程师）

## 技术决策：为什么 bin 用 Node 而非 .sh / .cmd

npm 只有一个 `bin` 字段，**无法按平台选择入口**，这会造成死锁：

- 指向 `.cmd` → Linux 生成的 shim 会把 Windows 批处理当 shell 执行
  （实际踩到：CI 报 `@echo: command not found`）
- 指向 `.sh` → Windows 无法直接执行

**解法**：`bin` 指向 `bin/ai-code-review.js`（Node + shebang）。
Node 是本工具链除 JDK 外唯一的依赖，两个平台原生可用；
入口内部按 `process.platform` 转发到对应启动器。

Windows 下 `spawnSync` 执行 `.cmd` 必须加 `shell: true`，否则静默无输出。

## 修复：注释掉的代码被误报（真实项目发现）

### 问题

在 `hccloud-material-science`（617 文件）上扫描，5 条 P1 里**4 条是误报**——
都是被 `//` 注释掉的 `e.printStackTrace()`：

```java
} catch (Exception e) {
//                    e.printStackTrace();
}
```

规则按行做文本匹配，没有识别注释。**注释掉的代码根本不会执行**，报出来是纯噪音。

真实项目是工具最好的验收场——样例样本造不出这种case。

### 修复

`ExceptionHandlingRule` 与 `HardcodedSecretRule` 增加注释行跳过：
- `//` 单行注释
- `/*` `*/` 块注释首尾
- `*` 开头的块注释中间行

### 效果

| 项目 | 修复前 P1 | 修复后 P1 |
|---|---|---|
| hccloud-material-science | 5（4 误报） | **0** |

### 回归验证

修复只减误报、不减真问题：

| 样本 | 预期 | 实际 |
|---|---|---|
| samples/bad-code | 24 条 / P0 7 / P1 5 | 24 / 7 / 5 ✅ |
| samples/good-code | 0 条 | 0 ✅ |

### 附带教训

Java 源码注释里**不能出现 `*/` 字面量**，会提前闭合 Javadoc 导致编译失败。
本次又踩了一次（注释里写「块注释首尾行（/** 与 */）」）。
同理，中文全角括号在注释里没问题，但字符串里用全角引号会破坏语法。

## 报告改为 HTML 优先输出（v1.1.0）

### 问题

原 Markdown 报告 2634 行纯列表堆叠：
- 每条都是「位置/级别/问题/证据/建议」五件套，扫一眼全是重复
- P0/P1 与 P3 平级并列，最该关注的和最该忽略的长得一样
- 想"只看必修的"得Ctrl+F 搜

### 方案

新增 `HtmlReport.java`，采用**仪表盘 + 按级别折叠**结构。

设计取自 `gzh-design` 技能的「石墨极简（Graphite Minimal）」主题
（`references/theme-graphite-minimal.md`，主色 `#52525B`，
定位"科技评论、专业观点"，全灰阶留白理性）。

**但不复用其 HTML 组件** —— 那是为微信公众号编辑器设计的，报告是工程产物，
且要能贴进 GitLab issue / PR 评论 / 邮件。因此只取设计变量
（配色、圆角、间距、字号），实现在 Java 侧，全内联样式。

### 改进点

| 改动 | 效果 |
|---|---|
| 顶部数字仪表盘 | P0/P1/P2/P3 四张卡，一眼看清严重程度分布 |
| 按级别折叠 | P0/P1 默认展开，P2/P3 默认收起 |
| 每条默认只显示一句话 | 位置/规则/证据/修法收进折叠层 |
| 人工边界置顶 | "本工具不覆盖"置于问题清单之前 |
| 干净度百分比 | "92% 干净" 比 "217 条问题" 更可信 |
| 扫描耗时 | 显示实际耗时 |

### 输出物

| 文件 | 读者 | 用途 |
|---|---|---|
| `review-report.html` | 人 | 仪表盘+折叠，可直接贴 issue / PR 评论 |
| `review-report.md` | AI / diff | 保留，供 AI 读取与版本对比 |
| `gitlab-comment.md` | 工程师 | 保持原样，可POST 到 MR |

### 验证

- 结构完整性：DOCTYPE / 闭合标签正常，440 处 details、219 处 summary
- 数据准确：material = 0/0/204/13；bad-code = 7/5/12/0
- 折叠逻辑：有 P0/P1 时 2 组自动展开，无则全收起
- HTML 转义：无 script 注入风险
- 回归：bad-code 24 条 / P0 7 / P1 5、good-code 0 条，全部不变

### 用法

```bash
ai-code-review <项目> ./out
# 打开 ./out/review-report.html
```
